# 2026-09-14

Six resistors were found carrying a wrong footprint. A footprint check was added
to the netlist checker, and the Stage 1 exit criterion was corrected.

## A 160-pin QFP on six resistors

`R7`–`R12`, the 10 kΩ pull-downs, carried the footprint
`Package_QFP:PQFP-160_28x28mm_P0.65mm` — a 28 × 28 mm, 160-pin quad flat pack.
It entered with the commit that drew R1–R12 on 2026-09-13, and was committed and
pushed while every document in the repository said "footprints not assigned".
The six fields are now cleared.

**Clearing them did not change the ERC count.** 44 before, 44 after:

| | Total | Made of |
|---|---|---|
| With the QFPs | 44 | 30 `pin_not_connected` + 8 empty + **6 `pqfp-160`** |
| After clearing | 44 | 30 `pin_not_connected` + 14 empty |

So the ERC report is checked by **composition, not by count**:

```bash
grep "footprint_filter" erc.rpt | sed 's/.*已分配封装 //;s/ 与封装筛选规则.*//' | sort | uniq -c
```

## Footprints are now compared against a map

`check_nets.py` now compares every component's footprint against
`expected_footprints` in the same JSON map, using the netlist it already parses.

**ERC cannot do this job.** `R1`–`R12` all declare the footprint filter `R_*`,
which `R_0805_2012Metric` and `R_Axial_DIN0207_...` match equally. Swapping the
series resistors with the pull-downs passes ERC at a clean 30 / 0.

The map was written before the footprints are assigned, so it fails today and the
failure prints the to-do list.

**The Stage 1 exit criterion is now two tests, not one:** ERC at exactly 30 / 0,
*and* `check_nets.py` at `ALL PASS` including the footprint block.

## Design rules committed

The 2-layer rules specified in `fabrication.md` are now in the project file:
0.3 mm minimum track, 0.3 mm clearance, 0.3 mm via hole with a 0.15 mm annular
ring, silk 0.2 mm line with 1.2 mm text. Default track width 0.4 mm.
`dimension_units` was reverted from `0` to `3`, KiCad's default.

## Documentation restructured

Devlogs are now one file per day, named `YYYY-MM-DD.md`. The ten existing entries
were merged into four. Every document states facts and plans; reasoning and
withdrawn-justification narration were removed, and each file now carries a
complete English version followed by a complete Chinese version rather than
alternating paragraphs.

# 2026-09-14 / 中文

发现六个电阻带着错误的封装。给网表核对脚本加上封装检查，并更正了第 1 阶段的完成判据。

## 六个电阻上装着 160 脚的 QFP

`R7`–`R12` 这六个 10 kΩ 下拉的封装是 `Package_QFP:PQFP-160_28x28mm_P0.65mm`——
一个 28 × 28 mm、160 脚的四方扁平封装。它随 2026-09-13 画 R1–R12 的那次提交进来，
已提交并推送，而当时仓库里每一份文档都写着"封装未分配"。六个字段现已清空。

**清掉它们，ERC 的计数没有变化。** 之前 44，之后还是 44：

| | 总数 | 组成 |
|---|---|---|
| 带着 QFP | 44 | 30 `pin_not_connected` + 8 个空 + **6 个 `pqfp-160`** |
| 清空之后 | 44 | 30 `pin_not_connected` + 14 个空 |

所以 ERC 报告要看**组成，不是看计数**：

```bash
grep "footprint_filter" erc.rpt | sed 's/.*已分配封装 //;s/ 与封装筛选规则.*//' | sort | uniq -c
```

## 封装现在也对着一张表比对

`check_nets.py` 现在用它本来就在解析的那份网表，把每个元件的封装与同一份 JSON 里的
`expected_footprints` 比对。

**ERC 做不了这件事。** `R1`–`R12` 声明的筛选规则都是 `R_*`，而 `R_0805_2012Metric` 和
`R_Axial_DIN0207_...` 一样匹配它。把串阻和下拉的封装对调，ERC 报的是干干净净的 30 / 0。

这张表是在封装分配之前写下的，所以它今天失败，而失败打印出来的就是待办清单。

**第 1 阶段的完成判据现在是两项，不是一项：** ERC 正好 30 / 0，**并且** `check_nets.py`
连封装那一段一起 `ALL PASS`。
