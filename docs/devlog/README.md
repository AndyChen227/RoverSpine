# Devlog

One file per day, named `YYYY-MM-DD.md`. A day with several results gets one
entry covering all of them, not several entries.

Each file is a complete English version followed by a complete Chinese version.

## What goes in

- What was done, decided, measured or found.
- Numbers: ERC counts, net counts, dimensions, prices, dates.
- What is still open, and what it blocks.
- Machine behaviour that will bite someone who does not know it — a check that
  stays silent on a real fault, a panel that does not refresh.

## What stays out

- Reasoning about why a decision was reached.
- Commentary on earlier reasoning, or on justifications that were withdrawn.
- Anything already stated in the planning documents.

**Days that produced a failure get an entry too.** A board that did not work,
written down so the cause is clear, is worth as much as one that did.

# 开发日志 / 中文

一天一个文件，命名 `YYYY-MM-DD.md`。一天里有多项结果就写在同一篇里，不拆成多篇。

每个文件是完整的英文版在前，完整的中文版在后。

## 写什么

- 做了什么、定了什么、量到了什么、发现了什么。
- 数字：ERC 条数、网络数、尺寸、价格、日期。
- 还没解决的事，以及它卡住了什么。
- 不知道就会吃亏的机器行为——比如某项检查对真实故障保持沉默、某块面板不会自动刷新。

## 不写什么

- 一个决定是怎么推出来的。
- 对早先推理的评述，或者某条理由如何被撤回。
- 规划文档里已经写过的内容。

**做失败的日子同样要写。** 一块没做成的板子，只要把原因写清楚，价值不比做成的低。
