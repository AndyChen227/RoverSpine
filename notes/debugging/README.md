# Debugging notes / 调试笔记

One file per problem worth remembering. Structure, following
[RoverPi's convention](https://github.com/AndyChen227/RoverPi/tree/main/notes/debugging):

**What happened · What it looked like · What the cause actually was · The fix ·
The lesson · What it cost**

A devlog entry records what a session produced. A note here records what a
mistake taught. Conclusions that were later retracted stay — RoverPi already
keeps one, and it is one of the more useful files in that repository.

每个值得记住的问题写一个文件。结构沿用 RoverPi 的约定：
**发生了什么 · 表面现象 · 真正的原因 · 怎么修的 · 教训 · 代价**。

开发日志记的是一次工作产出了什么，这里记的是一个错误教会了什么。**被推翻的结论
保留下来**——RoverPi 里已经有一个，而且是那个仓库里最有用的文件之一。
